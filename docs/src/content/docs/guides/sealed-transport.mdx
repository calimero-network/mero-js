A node speaks plain HTTP. Whatever TLS sits in front of it ends outside the
enclave, at a reverse proxy, a load balancer or a relay. Everything that crosses
that hop is readable there: your bearer token, the method you call, its
arguments and its result. A genuine attestation quote says what runs inside the
TEE. It says nothing about who reads the bytes on the way in.

Sealed transport encrypts each request to an X25519 key that the node's quote
commits to. Only the attested enclave can open the request, and only it can
produce a response the client accepts.

```typescript
import {
  MeroJs,
  createSealedFetch,
  fetchAttestedTransportKey,
} from '@calimero-network/mero-js';

const baseUrl = 'https://tee-node.example';

// 1. Attest once, and accept the key only if a quote you verified commits to it.
const probe = new MeroJs({ baseUrl });
const transportPublicKey = await fetchAttestedTransportKey(
  probe.admin,
  async ({ quoteB64, nonce, reportDataSuffix }) => {
    const result = await myOwnNode.admin.teeVerifyQuote({
      quoteB64,
      nonce,
      expectedApplicationHash: reportDataSuffix,
    });
    return (
      result.quoteVerified &&
      result.nonceVerified &&
      result.applicationHashVerified === true
      // && result.quote measurements are ones you accept
    );
  },
);

// 2. Every admin and RPC call from here on is sealed.
const mero = new MeroJs({
  baseUrl,
  fetch: createSealedFetch({ baseUrl, transportPublicKey }),
});
```

<Aside type="caution">
Verify the quote with something **other than the node being attested**: a node
of your own, or `calimero-tee-verify`. Asking the attested node to vouch for its
own quote proves nothing. Also check the measurements (MRTD, RTMRs) against the
releases you accept.
</Aside>

## What a proxy sees

One opaque `POST /sealed/v1` each way, with content type
`application/vnd.calimero.sealed`. Method, path, headers (the `Authorization`
header among them) and body are all inside the envelope. The node opens it and
routes the inner request exactly like a direct one, so auth and permissions
apply unchanged.

A request carries a timestamp and a one-time key, and the node accepts each key
once. A proxy that replays a captured request gets it refused. `createSealedFetch`
refuses any URL outside `baseUrl` rather than sending it in the clear.

## Errors

| Error | Meaning |
| --- | --- |
| `StaleTransportKeyError` | The node restarted and holds a new key. Call `fetchAttestedTransportKey` again and rebuild the fetch. |
| `SealedTransportError` | The node refused the envelope itself (`status`, `code`): malformed, undecryptable, outside the time window, or replayed. |

Errors from the inner request come back as ordinary responses, so the usual
`HTTPError` handling applies.

## Limits

- **No streams.** SSE and WebSocket connections cannot be sealed into one reply.
  The node answers a sealed stream request with a `501`. Open subscriptions over
  TLS you trust, or keep them to data you would publish anyway.
- **64 MiB** per sealed request and per sealed response.
- **Clock.** The node refuses a request more than five minutes off its clock.

The wire format (X25519 → HKDF-SHA256 → AES-256-GCM) is specified in core's
[security guide](https://calimero-network.github.io/core/operate/security/#sealed-transport-encrypting-to-the-tee).
