## At a glance

```ts
import { CalimeroClient, browserPasskey } from '@calimero-network/mero-js';

const client = new CalimeroClient({
  baseUrl: 'https://eu1.cloud.calimero.network',
  policy: { release: { minReleaseVersion: '2.3.109' } },
});
await client.signIn(browserPasskey());
const { result } = await client.view(appId, 'get', { key: 'a' });
```

Every request goes through the same three steps:

1. **Attest.** `GET /attestation` returns the node's TDX quote. The client
   verifies it in the page (Intel's signature chain, TCB status, the
   measurements of a signed mero-tee release) and that the quote binds the
   node's transport key and a fresh nonce.
2. **Seal.** The client opens a Noise NK session to that key and encrypts the
   request, credentials included, end to end to the enclave.
3. **Authorize.** The node checks the session token or API key inside the
   envelope, and routes the call to the app's replicated log.

The node side is [Calimero Core](https://calimero-network.github.io/core/)
1.0 (`merod`); this package is byte-compatible with core's `calimero-sealed`
and `calimero-client`.

<Aside type="note">
  Version 27 and later is the Calimero 1.0 client only. The v1 SDK (`MeroJs`,
  the admin and auth API clients, JSON-RPC, contexts and namespaces) is in
  26.x; see [Migrating from v1](/reference/migrating-from-v1/).
</Aside>
