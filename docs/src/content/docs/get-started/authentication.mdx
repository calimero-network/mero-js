Every credential travels inside the sealed envelope, so no proxy in the path
sees it. A client holds one credential at a time: a session or an API key.

## Passkeys

```ts
import { browserPasskey } from '@calimero-network/mero-js';

const passkey = browserPasskey(); // Touch ID, Windows Hello, a security key, a synced passkey
await client.signUp(passkey, 'alice'); // new account and passkey
await client.signIn(passkey);          // existing passkey
```

`browserPasskey()` wraps `navigator.credentials`. Anything that implements
`PasskeyProvider` (`create(options)` and `get(challenge, rpId, allowCredentials?)`,
answering base64url fields) works in its place, for example a software
authenticator in tests.

Each passkey is a device of the account:

```ts
const credentialId = await client.addPasskey(browserPasskey()); // another device
await client.labelPasskey(credentialId, 'work laptop');
await client.removePasskey(credentialId); // never the last one
```

## Sessions

`signUp` and `signIn` answer a `CalimeroSession`
(`{ accountId, sessionToken, expiresAt, refreshToken }`) and use it for every
request after. Keep it to resume without a passkey prompt:

```ts
const session = await client.signIn(passkey);
sessionStorage.setItem('calimero', JSON.stringify(session));

// another page load
const resumed = new CalimeroClient({ baseUrl, policy });
resumed.useSession(JSON.parse(sessionStorage.getItem('calimero')!));
await resumed.refresh(); // swap the refresh token for a new session
```

A refresh token is used once: a reused one revokes the session. A session is
signed by the node that issued it, so it can stop verifying when that node is
replaced or cannot be reached; the client then refreshes by itself, once, on
any node, and repeats the request
(see [Restarts and other nodes](/reference/error-model/#restarts-and-other-nodes)).
A session that refreshing cannot renew — expired, revoked, or a refresh token
already used — makes requests fail with [`LoginRequired`](/reference/error-model/).

Keep `client.session` after requests, not only after `signIn`: an automatic
refresh replaces it, and the refresh token you stored before is then spent.

```ts
await client.signOut();           // this session
await client.signOutEverywhere(); // every session of the account, on every device
```

## API keys

Agents and servers authenticate with an API key (`cal_...`), scoped and
revocable. The key is returned once.

```ts
const { keyId, key } = await client.createApiKey({
  label: 'ci',
  apps: [appId],      // only these apps
  methods: ['get'],   // only these methods
  readOnly: true,
  ttlSecs: 86_400,
});

const agent = new CalimeroClient({ baseUrl, policy });
agent.useApiKey(key);

await client.listApiKeys(); // never the keys themselves
await client.revokeApiKey(keyId);
```

## Confirmations

Some requests need the account holder's passkey over that exact request: a
method the app declares `confirm`, deleting an organization, upgrades,
transfers and approvals. The node answers `412 CONFIRM_REQUIRED` with a
challenge; the `*Confirmed` methods, and every method that takes a `passkey`,
sign it and send the request again.

```ts
await client.callConfirmed(app, 'clear', {}, passkey);
await client.postConfirmed(`orgs/${org}/outbound`, { package: 'com.example.kv' }, passkey);
```

A prompt the user dismisses rejects with `ConfirmCancelled`, and nothing more is
sent. An API key can answer a confirmation only if it was created with
`allowConfirm`.

<Aside type="note">
  A session opened from an app's own frontend (`{label}.{apps-domain}`) is bound
  to that package: it reaches only that package's apps and cannot create API
  keys, approve releases or upgrade.
</Aside>
