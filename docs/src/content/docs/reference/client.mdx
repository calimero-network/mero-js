```ts
// A Calimero Cloud cluster by name: its nodes come from the node directory,
// each attested under `policy` before anything is sent to it.
await CalimeroClient.connect({
  cluster: string,         // e.g. 'eu-shared-1'
  policy: CloudPolicy,
  directory?: string,      // default DEFAULT_DIRECTORY (Calimero Cloud's)
  zone?: string,           // try this zone's nodes first
  fetch?: typeof fetch,
  retry?: { retries?: number; baseDelayMs?: number; maxDelayMs?: number },
  random?: () => number,   // for the weighted order; default Math.random
}) // throws DirectoryError (reason 'unreachable' | 'not-found' | 'bad-response' | 'empty')

// A fixed list of nodes, or a cluster you run yourself.
new CalimeroClient({
  baseUrl: string,         // one node of the cluster
  nodes?: string[],        // other nodes, moved to on 421 WRONG_NODE or when one stays unavailable
  policy: CloudPolicy,     // which nodes to trust; see Trust and the sealed channel
  fetch?: typeof fetch,    // carries attestation and envelopes; default the global fetch
  retry?: { retries?: number; baseDelayMs?: number; maxDelayMs?: number }, // default 6, 200 ms, 2 s
})
```

`client.nodeUrl` is the node in use and `client.nodes` every node the client
may move to. Every route below is sent inside the sealed channel. `passkey` is a
`PasskeyProvider` (`browserPasskey()` in a page); a method that takes one
answers the node's `412 CONFIRM_REQUIRED` with it.

## Package origins

A package's managers register the web origins of a frontend they host
themselves, so it can sign people in with passkeys. A session opened there is
bound to the package. See
[Sign in from your own site](/get-started/authentication/#sign-in-from-your-own-site).

| Method | Route |
| --- | --- |
| `packageOrigins.list(package)` → `PackageOrigin[]` (`{ origin, rpId, addedBy, addedAt, served }`) | `GET package-origins/{package}` |
| `packageOrigins.add(package, origin, passkey?, { rpId?, served? })` → `{ package, origin, rpId, addedBy, addedAt, served }` | `POST package-origins/{package}` (`412` over `__add_origin`) |
| `packageOrigins.remove(package, origin, passkey?)` → `{ package, origin, removed: true }` | `DELETE package-origins/{package}` (`412` over `__remove_origin`) |

`add` refuses with `BadOrigin` (`BAD_ORIGIN`, `BAD_RP_ID`), `OriginTaken` and
`QuotaExceeded`; `list` and `remove` with `NotFound`. Without a passkey the
`412` reaches the caller as `ConfirmRequired`.

`served: true` registers a custom domain: the cluster also serves the
package's frontend on it from the signed bundle. The origin must be
`https://host` with no port, and the consent the passkey signs names it
(`{ origin, rpId, served: true }`). It further refuses with `NotServing` (the
cluster serves no frontends), `ClusterNotUpgraded` (a node is on an older
release), `QuotaExceeded` (4 served per package, 64 per cluster) and
`OriginTaken` (held with the other `served`; remove it first).

## Approvals and the consent page

The approval routes above refuse a session opened on an app's frontend
(`403`). An app sends its user to the node's consent page instead
([guide](/guides/user-approvals/)).

| Method | Route |
| --- | --- |
| `appsReport(org \| null, { after?, limit? })` → `AppsReport` | `GET orgs/{org}/apps` or `auth/apps` |
| `appsReportAll(org \| null)` → `AppsReport` (every page) | the same, following `next` |
| `releaseRules()` → `{ governance, deadlines }` | `GET releases` |
| `pendingApprovals(org?)` → `PendingApprovals` | `GET auth/apps` (or `orgs/{org}/apps`), `GET releases` |
| `requestConsent(request)` → `{ requestId, url, expiresAt, code? }`; show `code` to the user before sending them to `url`, and they should see the same code on the page | `POST consent/requests` |
| `openConsentPage(request, navigate? \| { navigate?, confirm? })`: checks `code` against `confirmationCode(requestId)` (else `CalimeroError` `CONSENT_CODE_MISMATCH`), runs `confirm(started)` so the app can show `code`, and navigates unless it answers `false` | `POST consent/requests`, then navigates to `url` |
| `consentResult(requestId)` → `{ requestId, kind, status, decidedAt }` | `GET consent/{id}/result` |
| `waitForConsent(requestId, { intervalMs?, signal?, expiresAt? })` | polls `GET consent/{id}/result` |

## Any route

`get`, `post`, `put` and `delete(path, body?)` send any request through the
sealed channel with the client's credential and map a refusal to a typed error.
`postConfirmed(path, body, passkey)` and `deleteConfirmed(path, passkey, body?)`
answer a `412 CONFIRM_REQUIRED`.

## Not covered

- The rest of `/ops/*`, the operator's API: use core's `meroctl`.
- `/apps/{app}/attestation` and receipt verification (core's
  `Client::verify_app_cluster`, which checks every replica's receipt key and the
  cluster's governance): not yet in this client.
- `/internal/*`: node to node only.
